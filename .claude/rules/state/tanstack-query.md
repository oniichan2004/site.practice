# TanStack Query Rules

This project does **not** hand-write `queryFn`/`queryKey` or wrap queries in custom
hooks. Every request goes through the oRPC contract via the `apiContracts` helper,
which generates the query key, the fetcher, and the mutation function for you.

## 0. The single entry point: `apiContracts`

`apiContracts` is built once from the typed oRPC client and exported from
`@/lib/api/client`:

```typescript
// lib/api/client.ts
export const apiContracts = createTanstackQueryUtils(adminClient);
```

It mirrors the contract tree, so every procedure exposes ready-made helpers:

```typescript
apiContracts.<namespace>.<procedure>.queryOptions({ input, ...options })
apiContracts.<namespace>.<procedure>.mutationOptions({ ...options })
apiContracts.<namespace>.<procedure>.key()          // partial-match key (invalidation)
apiContracts.<namespace>.<procedure>.queryKey({ input }) // full-match key
apiContracts.<namespace>.key()                      // partial key for a whole router
```

`<namespace>` is the contract router (`trips`, `inventory`, `tripSearch`,
`adminBookings`, `seatAddons`, ...). The input/output types come from the
contract — never redeclare them.

## 1. Use the helpers inline — do NOT write wrapper hooks

❌ **Do not** create `useTripSearch`, `useSeatMap`, `useDirectSale`-style hooks that
just wrap a single query/mutation. Call `useQuery`/`useMutation` directly in the
component with the contract helper.

```tsx
// ❌ Wrong — needless hook wrapper around one query
export function useSeatMap(tripId: string) {
  return useQuery({ queryKey: ["inventory", "seatMap", tripId], queryFn: () => ... });
}

// ✅ Correct — inline in the component, key + fetcher generated by the contract
const { data, isLoading, isError } = useQuery(
  apiContracts.inventory.getSeatMap.queryOptions({
    input: enabled ? { id: tripId, fromStopId, toStopId } : skipToken,
    refetchInterval: 10_000,
    staleTime: 5_000,
  }),
);
```

A custom hook is only justified when it adds real logic beyond a single call
(e.g. debounce + derived state + a query, reused in 2+ places). Extracting per
`react/hooks-rules.md` still applies — but the bar is "meaningful shared logic",
not "wrap one request".

## 2. Queries — `queryOptions`

```tsx
"use client";
import { useQuery } from "@tanstack/react-query";
import { apiContracts } from "@/lib/api/client";

const { data, isLoading, isError } = useQuery(
  apiContracts.trips.getInOrg.queryOptions({ input: { id: tripId } }),
);
```

- `input` is the procedure's typed input — fully checked against the contract.
- The **query key is generated** from the path + input. Never pass `queryKey`.
- Pass any TanStack option straight through: `staleTime`, `refetchInterval`,
  `placeholderData`, `select`, etc.

```tsx
const searchQuery = useQuery(
  apiContracts.tripSearch.search.queryOptions({
    input: searchParams ?? skipToken,
    placeholderData: keepPreviousData,
  }),
);
```

## 3. skipToken — not `enabled: false`

Make a query conditional by passing `skipToken` as the `input` (type-safe — the
fetcher is never called and `data` is correctly typed as possibly `undefined`).

```tsx
import { skipToken } from "@tanstack/react-query";

// ✅ Preferred — skipToken as input
useQuery(
  apiContracts.inventory.getSeatMap.queryOptions({
    input: enabled ? { id: tripId, fromStopId, toStopId } : skipToken,
  }),
);

// ✅ Also fine when the input is always valid but should pause — use `enabled`
useQuery(
  apiContracts.inventory.getSeatMap.queryOptions({
    input: { id: trip.id, fromStopId, toStopId },
    enabled,
  }),
);

// ❌ Wrong — never fake the input with `!` just to satisfy types
useQuery(
  apiContracts.inventory.getSeatMap.queryOptions({
    input: { id: tripId!, fromStopId: fromStopId!, toStopId: toStopId! },
    enabled: !!tripId,
  }),
);
```

## 4. Mutations — `mutationOptions`

```tsx
const queryClient = useQueryClient();

const directSale = useMutation(
  apiContracts.adminBookings.directSale.mutationOptions({
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: apiContracts.bookings.key() });
    },
    onError: (error) => handleSalesError(error, locale),
  }),
);

// The argument to `.mutate` IS the procedure input — typed from the contract.
directSale.mutate(input, {
  onSuccess: (booking) => setSaleResult(booking),
  onError: (err) => setErrorMsg(handleSalesError(err, locale)?.message),
});
```

- `mutationFn` is provided by the helper — just pass `onSuccess`/`onError`/etc.
- The value passed to `.mutate(x)` is the contract input; the resolved value is
  the contract output (JSON-serialized — `Date` → `string`).

## 5. Cache invalidation — use generated keys

Build invalidation keys from the same helpers (partial match), never hand-rolled
arrays — manual `["bookings"]` keys will **not** match contract-generated keys.

```typescript
const queryClient = useQueryClient();

// All queries under a router
queryClient.invalidateQueries({ queryKey: apiContracts.trips.key() });

// A specific procedure (any input)
queryClient.invalidateQueries({ queryKey: apiContracts.trips.listInOrg.key() });

// A specific procedure + input
queryClient.invalidateQueries({
  queryKey: apiContracts.trips.getInOrg.key({ input: { id: tripId } }),
});
```

`.key()` returns a **partial-match** key (good for invalidation). Use
`.queryKey({ input })` only when you need the **exact** key (e.g. `setQueryData`).
Some TanStack APIs want a plain `QueryKey`; cast with `as QueryKey` if needed.

## 6. One-off calls outside React

For imperative calls (event handlers that aren't mutations, server-side, combining
calls inside a single `mutationFn`), use the named client exports — not `useQuery`:

```typescript
import { tripsClient } from "@/lib/api/client";

const trip = await tripsClient.getInOrg({ id }); // typed, JSON-serialized
```

## 7. Query key shape (reference)

Contract-generated keys look like `[[...path], { type, input }]`, e.g.
`[["trips", "getInOrg"], { type: "query", input: { id } }]`. You rarely read these
directly — always derive them with `.key()` / `.queryKey()`.

## 8. Always handle all states

```tsx
const { data, isLoading, isError } = useQuery(
  apiContracts.tripSearch.search.queryOptions({ input: params ?? skipToken }),
);

if (isLoading) return <SearchSkeleton />;
if (isError) return <ErrorMessage />;
if (!data?.items.length) return <EmptyState message="No trips found" />;

return <ResultsGrid items={data.items} />;
```

For sales/booking endpoints, resolve localized error messages with
`handleSalesError` from `@/lib/api/errors`.
